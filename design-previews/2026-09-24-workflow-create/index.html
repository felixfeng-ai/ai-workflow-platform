新建工作流 · 布局与极简化 — 4 个方案

两件事一起改：① 画布太小（当前 1024px 弹窗里只剩 504px 画布，放不下第二个节点，创建按钮被顶到屏幕外）；② 要填的太多（当前必须填名称，另有描述、模板、定时共四组）。极简化的方向就是用户少决定，AI 多决定。

方案 A · 两步式最小改动

风险最低

第一步只问名字（可留空自动命名），点「创建并编辑」后进入全屏编辑器。描述、模板、定时全部移到编辑器里再设。

1 项打开时必填
944px画布宽度
右上固定主按钮位置

方案 B · 一句话起手推荐

对应「AI 自主决策」

打开就是一个输入框：「你想让它做什么？」AI 据此起草名字 + 步骤 + 参数 + 建议定时，落到全屏画布上。用户是审阅者而不是填写者 —— 没有必填项，画布和手动编辑一样都在。

0 项打开时必填
944px画布宽度
1 句用户需决定的事

方案 C · 意图直跑最激进

无画布

没有画布。用户描述目标，运行时由 LLM 逐步决定调哪个助手、要不要再来一轮 —— 这就是 ReAct 循环。最接近「LLM 自主决策」，但执行前看不到会跑什么。

0 项打开时必填
—画布宽度
不可预览执行前

方案 D · 零弹窗，直接进画布

步骤最少

点「新建工作流」不再弹任何东西，直接落到全屏空白画布。元数据压成顶部一行内联可编辑：名字先显示「未命名工作流」，要改才点。定时收进一个「⏱ 定时」按钮。

0 项打开时必填
944px画布宽度
0 次弹窗打断

为什么现在会这样 — 两个问题的根因

画布 504px 是算出来的，不是感觉。弹窗 max-w-5xl = 1024px，减去 p-5 内边距、左侧助手栏 w-44（176px）、右侧配置栏 w-72（288px）、两处 gap-2（16px），剩 504px。一个节点占 276px（NODE_W 220 + X_GAP 56），所以横向只放得下 1.8 个节点。
创建按钮被顶出屏幕，是缺一行 overflow-y-auto。弹窗容器是 max-h-[80vh] flex flex-col，但里面没有滚动，子元素（模板区、定时区）又不可压缩，于是内容溢出而不是滚动 —— 底部的按钮就掉到视口外了。画布同时从声明的 h-[50vh]（423px）被挤到 min-h-[360px] 的地板。
根因是一个 IDE 被塞进了弹窗。左侧助手栏 + 中间画布 + 右侧配置栏，本来就是编辑器级别的三栏，却和一个元数据表单共享 1024px。Dify / Coze / n8n / Langflow 全用两步：小弹窗只问元数据 → 全屏编辑器干活。四条规则里当前违反了三条：元数据没有和画布分开 / 画布没有占满视口 / 侧栏不会按需出现。

「要填的太多」和「AI 自主决策」是同一件事

字段多，是因为预设式编排要求用户提前想清楚一切。名称、描述、模板、定时、每个节点用哪个助手、每个参数填什么 —— 这些全是「决策」，用户必须在点创建之前就做完。极简化的唯一出路是把决策权交出去：用户只给意图，其余由 AI 起草。
这就是方案 B 的位置 —— 它不删画布。AI 起草的图仍然落到画布上，用户能看见、能改、能删。自主决策不等于放弃控制权，而是把「从零构造」换成「审阅修改」。
方案 C 才是真的不要画布，也是唯一有硬代价的那个。没有图 = 没有执行前预览、没有断点续跑、没有条件分支可视化，出问题只能看日志。它以「用户完全信任模型」为前提，而当前项目的定位（多租户、可审计、有 checkpointer 断点续跑）恰好建立在「执行前能看到图」之上。所以建议把它当作一个节点内部的运行时模式（某个助手内部走 ReAct 循环），而不是整个工作流的形态 —— 骨架仍然是图。

建议的组合

布局取 D（零弹窗全屏画布）+ 入口取 B（一句话起手）：点「新建工作流」直接进全屏画布，画布中央是那句输入框而不是操作指引 —— 想清楚了就输入一句话让 AI 起草，想自己搭就点「从空白开始」把它关掉。
这样两个问题一次解决：弹窗没了（画布 504→944px），必填项从 1 个变成 0 个（一句意图即可），而画布、分支、断点续跑这些已有的能力一个都不用动。
