## 1. 平台现状盘点（基于代码）

当前能力栈：

- **极简工作区**：项目 / 任务 / 笔记（多租户数据隔离）
- **知识库 RAG**：文档上传 → 分块 → 向量检索（document + document_chunk）
- **AI 智能体**：内置 周报 / 巡检报告 / 竞品调研 / 面试题 + 自定义 Agent + 参数预置模板
- **可视化工作流编排**：React Flow 画布 + DAG 执行器 + 定时调度（scheduler）
- **移动端**：微信小程序（登录 / 工作台 / 项目 / 智能体，4 页面 + 底部导航）
- **触达**：微信订阅消息
- **部署**：Web 单页应用 + FastAPI 后端，Docker Compose 私有化部署 + GitHub Actions 自动更新

一句话定位：**把「项目协作 + 知识管理 + AI 自动化」塞进一个极简界面的轻量 AI 办公工作台**。

## 2. 竞品对比

| 维度 | 金山 WPS AI | 字节 豆包办公 | GitHub | **雅秩（当前）** |
|---|---|---|---|---|
| 产品形态 | 办公套件 + AI 副驾 | AI 原生办公全家桶 | 开发者协作平台 | 轻量 AI 工作台 |
| 核心入口 | 文件/文档 | AI 对话助手 | 代码/Issue/PR | 项目/任务/工作流 |
| 文档能力 | 极强（格式兼容是壁垒） | 强（文档/表格/脑图） | 弱（Markdown 仓库） | 仅笔记，无文档 |
| AI 能力 | 写作/润色/PPT/表格公式 | 大模型全家桶 + Agent | Copilot 代码生成 | 智能体 + 工作流 + RAG |
| 自动化 | 弱 | 中（+飞书自动化） | 强（Actions/CI） | 强（工作流+定时+微信触达） |
| 多人协作 | 云文档实时协作 | 飞书生态 | 全球开发者协作 | 同租户共享，无实时协作 |
| 生态/集成 | 极广 | 字节内容生态 | 极强（API/市场/CI） | 无集成，孤岛 |
| 部署 | 纯云 | 纯云 | 纯云 | **可私有化（差异化）** |
| 移动端 | App 全功能 | App 全功能 | App | 微信小程序，仅 4 页面 |
| 商业模式 | 会员 + 企业授权 | 订阅 + AI 计费 | Freemium + 订阅 | 未商业化 |

**关键洞察**：三家巨头都是「从内容入口长出 AI」，雅秩 是「从任务入口长出 AI」。内容入口竞争红海，**任务/自动化入口仍是空档**。前提是别做全套，而是把「AI 替你干活」做到极致。

## 3. 「极简化 + AI化办公」理念验证

方向正确，执行差一半。

**✅ 对的一半**：智能体 + 工作流编排 + 知识库 RAG，确实在实践「让 AI 干活而非让用户学软件」。GitHub Actions 证明该模式在开发领域的价值，已将其迁移到办公领域。

**❌ 差的一半**：
1. **入口仍是「点菜单」，不是「说话指挥」**。豆包/微软 Copilot 均为对话优先——打开就是 AI 助理，说人话生成文档/任务/流程。当前 AI 藏在「创建智能体 → 填参数 → 运行」三步之后，极简化退化为「功能少」，而非「设计精」。
2. **AI 化缺「结果闭环」**。RAG 有底层，但缺「问知识库」「引用来源」「知识库驱动 Agent」等让用户**看见** AI 价值的界面。
3. **自动化缺「无人值守」叙事**。定时调度 + 微信触达已实现，但产品上未将「AI 每周五自动生成周报推给你」包装成卖点。

## 4. 当前能力缺口与优先级（2026-11-08 基于当前代码复核）

### 4.1 核心判断

结合雅秩「轻量 AI 工作台」的定位，当前最缺的不是更多项目管理模块，而是五个闭环：

1. AI 产出能否真正落地成业务动作。
2. AI 工作流能否被业务事件触发。
3. AI 执行前能否让人确认和审批。
4. 团队能否围绕任务进行基本协作。
5. 平台能否接入外部系统并稳定运营。

如果优先补齐 Sprint、Epic、JQL、甘特图等 Jira 能力，反而会把产品拖向重型项目管理软件，偏离「AI 把活干完，人只看结果」的核心定位。

### 4.2 P0：最影响核心定位的缺口

| 缺口 | 当前情况 | 应该补什么 |
|---|---|---|
| AI 产出没有真正落地 | 工作流结果主要停留在运行记录和通知里，不能自动变成任务、文档、知识条目或外部动作 | 增加“写入动作节点”：创建任务、更新任务、生成文档、写知识库、发送通知、调用 Webhook |
| 工作流只有智能体节点 | 当前节点核心是选择一个 Agent 执行，缺少通用动作能力，见 [workflow.py](../backend/app/models/workflow.py#L9) | 增加 Agent、工具调用、HTTP 请求、条件、等待、人工审批、创建任务、发送消息等节点类型 |
| 只有手动和定时触发 | 目前触发方式是手动运行或 cron/固定间隔，不能响应业务事件 | 增加任务创建、任务逾期、文档上传、表单提交、Webhook 接收等事件触发 |
| 没有人工介入机制 | 工作流只能成功或失败，不能“跑到一半等人确认” | 增加审批节点、暂停等待、草稿确认、人工修改后继续执行 |
| 任务协作基础不足 | 任务只有标题、描述、优先级、三态状态和截止日期，没有负责人、评论和操作历史，见 [task.py](../backend/app/models/task.py#L18) | 至少补负责人、评论、@提醒、活动记录、标签和附件 |
| 无人值守执行不够可靠 | 调度器是进程内单例，工作流失败后可以续跑，但没有完整的自动重试、退避和并发控制策略，见 [scheduler.py](../backend/app/workflows/scheduler.py#L42) | 增加重试策略、超时、取消、幂等控制、运行队列、失败告警和多实例调度锁 |

其中优先级最高的是 **动作节点 + 人工审批 + 事件触发**。现在的工作流更像“定时生成报告”，还不是“定时完成工作”。这三项补上后，平台才会从 AI 报告工具变成 AI 执行平台。

### 4.3 P1：平台化和获客必需的缺口

1. **Jira、飞书、Notion、GitHub 连接器**
   雅秩的战略不是替代 Jira，而是做现有工具的 AI 执行层。因此应优先做 Jira 连接器，而不是复制 Jira 功能。至少需要同步项目、Issue、状态、负责人和评论，并支持导入。

2. **开放 API、Webhook 和 API Key**
   没有这些能力，雅秩很难接入企业微信、钉钉、邮件、日历和其他业务系统，也就无法成为真正的 AI 执行层。

3. **全局搜索与统一上下文**
   用户需要能搜索任务、笔记、文档、知识库、智能体和工作流，并让 AI 基于搜索结果和选定对象工作。

4. **更多通知渠道**
   目前主要是站内通知和微信订阅消息。实际团队还需要邮件、企业微信、钉钉、飞书群机器人和 Webhook 通知。

5. **数据导入导出**
   需要 CSV、Markdown、Notion 和 Jira 导入，以及工作区整体导出。私有化客户尤其关心数据可迁移性。

6. **模板中心**
   当前有少量内置工作流模板和参数模板，但缺少可浏览、可复制、可分享的场景模板库。

7. **AI 成本和调用治理**
   需要按租户或用户统计 token、调用次数和失败率，配置额度、告警和模型路由。

8. **移动端补齐工作流和知识库**
   小程序目前主要覆盖工作台、项目和智能体。如果增加审批节点，移动端必须能收到待审批任务并直接处理。

### 4.4 P2：企业客户和规模化能力

- 项目级权限，而不只是租户级 owner/member/readonly。
- 审计日志，记录谁改了什么、谁触发了什么工作流、AI 执行了什么动作。
- SSO、LDAP、企业组织架构同步。
- 工作流版本管理与回滚。
- 完整运行追踪：每个节点的输入、输出、耗时、模型、token、错误和重试记录。
- 多实例部署下的分布式调度和任务队列。
- 管理后台：成员、模型、额度、通知渠道和系统健康状态。

### 4.5 暂不建议直接补齐的 Jira 功能

以下能力可以等有明确客户需求后再做，不应作为当前主线：

- 自定义 Issue 类型和复杂字段体系。
- 自定义状态机、权限方案和界面方案。
- Sprint、Epic、Backlog、依赖关系和燃尽图。
- JQL 查询语言。
- 甘特图和复杂项目组合管理。
- 完整的多人实时文档协作。

### 4.6 最小优先级建议

如果当前只做三件事，建议按以下顺序：

1. **工作流动作节点和结果写入**：让 AI 的产出能创建任务、生成文档、发通知、调用外部接口。
2. **事件触发和 Webhook/API**：让工作流从“定时任务”变成业务事件驱动。
3. **人工审批和任务协作基础**：让团队敢用、能接手、能追踪。

一句话总结：雅秩当前最缺的不是“更多管理功能”，而是 **AI 从生成结果到改变业务状态的完整闭环**。先把这个闭环做通，再通过 Jira、飞书、Notion、GitHub 连接器接入现有工作流，比直接做一个“AI 版 Jira”更有机会。

## 5. 商业化完善路径

### 5.1 四层订阅（SaaS）

| 层级 | 目标 | 卖点 | 参考价 |
|------|------|------|--------|
| 免费版 | 引流 | 单人、基础 AI 额度、核心功能 | ¥0 |
| 专业版 | 个人付费 | 高 AI 额度、自定义 Agent、工作流全量、模板 | ¥29-49/月 |
| 团队版 | 小团队 | 多人、角色权限、共享知识库、管理后台 | ¥99-199/月 |
| 企业版 | 中大型 | **私有化部署 + SSO + 审计 + SLA + 专属模型通道** | 按年授权 |

### 5.2 私有化部署授权（最强杠杆）
Docker 部署栈与 GitHub Actions 自动更新均现成。国内大量中小企业对数据上云有顾虑，「一键私有化 + 可定制工作流」是真实付费点：一次性授权 + 年维护费 + 定制工作流开发。

### 5.3 AI 按量计费
token 额度包（月度套餐 + 超额按量），成本可预测，兼作防滥用闸门。

### 5.4 模板市场抽成
Agent / 工作流 / 提示词模板，创作者分成，形成「用的人越多 → 模板越多 → 越好用」网络效应。

### 5.5 微信生态变现
小程序 + 订阅消息低成本触达，企业微信打通后是团队版核心卖点。

### 5.6 价格锚点
比豆包/飞书便宜、按需付费、可私有化，主打「够用、轻、数据可控」。

## 6. 功能 Roadmap

### 阶段一（1-3 个月）——立竿见影，补齐理念缺口
1. **AI 对话副驾**：全局对话入口「帮我写周报」「总结这个项目」「创建竞品调研任务」→ 自动调度 Agent / 工作流（最高优先级）
2. Markdown 文档编辑器 + AI 写作（续写/润色/总结）
3. 站内通知中心 + 到期提醒
4. 看板视图（拖拽任务列）
5. 团队管理 UI + 角色权限
6. 模板库（智能体 / 工作流 / 提示词一键套用）

### 阶段二（3-6 个月）——从单机到协作平台
7. 实时协作 + 评论 + @提醒
8. 报表与统计（生产力、AI 使用量）
9. 数据导入导出（CSV / Markdown / Notion）
10. 小程序补齐（工作流审批、知识问答、通知）
11. API + Webhook
12. 集成（企业微信 / 钉钉 / 邮件 / 日历）

### 阶段三（6-12 个月）——生态与护城河
13. 插件市场
14. 多模型切换 + 本地 Ollama
15. 国际化
16. 审批流 + 审计日志（企业版前置）

## 7. 战略建议

差异化三个钩子：
1. **对话式指挥**：打开就是 AI 助理，不是功能菜单
2. **结果导向**：AI 直接产出周报/报告/计划，不是给模板让用户填
3. **无人值守自动化**：定时跑 + 微信推送，AI 跑完用户只收结果

三个钩子成立，「极简化 + AI化办公」就从口号变成产品本身。
